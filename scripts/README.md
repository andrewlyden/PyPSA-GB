# scripts

The Python code of the workflow, by functional area. Most modules are run by a Snakemake rule (`rules/*.smk`,
`script:` or `shell:`) and read `snakemake.input`, `.output` and `.params`; shared code is imported as
`scripts.<folder>.<module>`. The documentation's module index (`docs/source/reference/api/index.md`, generated by
`utilities/build_reference_tables.py`) lists every module with its one-line purpose.

| Folder | What it holds |
|--------|---------------|
| `CP30/` | NESO Clean Power 2030: data extraction, the brownfield fleet, and the build, energy, locational and dispatch checks |
| `FES/` | NESO Future Energy Scenarios: download, building blocks, prices and FES-specific checks |
| `sources/` | Scenario sources: the pathway and GSP registries, raw NESO downloads, the FES and CP30 adapters, new-year helpers |
| `network_build/` | The ETYS, Reduced and Zonal networks, ETYS Appendix B upgrades and branch units |
| `network_clustering/` | Clustering and component aggregation, boundary and zone bus maps |
| `demand/` | Base demand, its disaggregation (EVs, heat pumps, ...) and consumer flexibility |
| `renewables/` | Site data, weather profiles (wind, solar, hydro, marine) and support labels |
| `generators/` | Thermal and renewable integration (DUKES, REPD, TEC, FES), marginal costs and their calibration |
| `storage/` | Batteries, pumped hydro and other storage from REPD, TEC and FES |
| `hydrogen/` | Electrolysers, hydrogen storage and hydrogen turbines |
| `interconnectors/` | Interconnector registers, availability, historical flows and foreign prices (ENTSO-E, TYNDP, CP30) |
| `solve/` | Network finalisation, secured boundaries and the optimisation |
| `market/` | Two-stage market dispatch (wholesale and balancing mechanism), bids and offers, support schemes, accounting |
| `consumer_bill/` | The household electricity bill built from the solved market |
| `public_ownership/` | Post-solve financing and ownership accounts for the public-ownership cases |
| `analysis/` | Results analysis, notebooks, explorers and documentation figures |
| `utilities/` | Shared helpers: logging, scenario detection, spatial mapping, carriers, cutouts, network I/O |

`validate_scenarios.py` (in this folder) checks the scenarios that `config/config.yaml` selects before a run:

```bash
python scripts/validate_scenarios.py              # configuration and weather cutouts
python scripts/validate_scenarios.py --no-files   # configuration only
```

Scripts run as `python scripts/...` put the repository root on `sys.path` before importing `scripts.*`.
